Traffic Density Control for Heterogeneous Highway Systems

Constrained traffic control for mixed autonomous and human-driven vehicles using Feedback Linearization and Model Predictive Control.

Overview

This project addresses traffic congestion in heterogeneous highway corridors containing both autonomous vehicles (AVs) and human-driven vehicles (HVs). Traffic dynamics are represented using a heterogeneous METANET model, while variable speed commands are used to regulate vehicle densities and move congested cells toward free-flow conditions.

The main challenge is that the traffic dynamics are nonlinear while the actual speed-control commands are physically constrained. A hybrid Feedback Linearization–Model Predictive Control (FL–MPC) architecture addresses these two problems together. Feedback Linearization transforms the nonlinear density dynamics into a linear input-output form, while MPC determines the virtual control commands subject to the physical limits.

Main idea: use Feedback Linearization to handle the nonlinear traffic dynamics and MPC to enforce physical control limits, with a new constraint-mapping method connecting the virtual MPC commands to the actual variable-speed commands.

Heterogeneous Highway Model

The highway is divided into a sequence of cells. Each cell contains AVs and HVs, and each class is characterized by its density, average velocity, and traffic flow. For vehicle class \(c \in \{A,H\}\), conservation of vehicles gives

\[ \dot{\rho}_{i,c}(t) = \frac{1}{\ell_i\gamma_i} \left(q_{i-1,c}(t)-q_{i,c}(t)\right), \qquad q_{i,c}=\rho_{i,c}v_{i,c}. \]

Here, \(\rho_{i,c}\), \(v_{i,c}\), and \(q_{i,c}\) denote density, average velocity, and outflow. The heterogeneous METANET formulation also captures interactions between the vehicle classes and distinguishes free-flow, semi-congested, and congested operating regions.

Control Objective

The objective is to regulate the AV and HV densities of congested cells toward desired reference densities. The control action is implemented through suggested vehicle velocities:

\[ U_{i,c}=(1-u_{i,c})V_{i,c}, \qquad 0\leq u_{i,c}\leq u_{i,c,\max}. \]

The controller must therefore reduce congestion without requesting inadmissible speed commands. Because a cell's density depends on both incoming and outgoing traffic, density regulation involves commands applied to neighboring cells, leading to an over-actuated control problem.

1. Feedback Linearization

Traffic density is selected as the controlled output. Differentiating density until the control commands appear gives, for a block of adjacent cells,

\[\ddot{\rho}_{c}=F_c+G_cu_c.\]

A right-inverse matrix \(H_c\) is selected such that

\[G_cH_c=I.\]

The feedback-linearizing control law is

\[u_c=H_c\left[-F_c+\nu_c\right],\]

which transforms the nonlinear density dynamics into

\[\boxed{\ddot{\rho}_c=\nu_c}.\]

The signal \(\nu_c\) is a virtual control input. Instead of selecting it with a conventional FL tracking law, MPC determines it so that the resulting physical commands \(u_c\) remain feasible.

2. Model Predictive Control

After Feedback Linearization, MPC operates on the linearized density dynamics. At each control step it predicts future density evolution and chooses virtual commands that balance reference tracking, control effort, and smooth command changes.

\[ J_c = \sum_{j=0}^{N_p} \left( \|y_c(k+j)-\rho_c^{*}(k+j)\|_{Q}^{2} + \|\nu_c(k+j)\|_{R}^{2} + \|\Delta\nu_c(k+j)\|_{S}^{2} \right). \]

MPC computes \(\nu_c\), but the physical constraints are imposed on \(u_c\). A constraint-mapping method is therefore needed to connect the two.

3. Constraint Mapping for the Over-Actuated System

Substituting the FL control law into the physical input bounds maps the admissible actual commands into inequalities on the virtual command:

\[ H_cF_c \leq H_c\nu_c \leq H_cF_c+u_{c,\max}. \]

Since there are more physical control inputs than controlled density outputs, \(G_c\) is rectangular and the choice of right inverse matters. Using only the Moore–Penrose pseudoinverse can produce an unsuitable or infeasible virtual-command constraint set.

The proposed method exploits the null space of \(G_c\). A family of valid right inverses can be expressed as

\[ H_c=G_c^{\dagger}+\Phi_c\Lambda_c. \]

Candidate matrices are generated so that one row of \(H_c\) becomes zero, converting the overdetermined constraint mapping into a solvable square form.

At each update: candidate constraint mappings are constructed, the MPC problem is solved for each candidate, and the solution with the minimum MPC cost is selected. Its virtual command is then converted into the actual speed-control command through Feedback Linearization.

4. Real-Time Reference Density Generation

Reference selection is more complicated in heterogeneous traffic than in a single-class highway. A mixed AV/HV system has two density coordinates and several traffic phases, so a single critical-density reference is insufficient.

For a congested cell, the proposed method uses the current AV/HV density combination and identifies a desired density pair on the free-flow boundary. The reference therefore adapts to both congestion severity and AV-to-HV traffic composition.

Overall Control Procedure

Measure → Generate Reference → Linearize → Map Constraints → Optimize → Apply
  1. Measure the current AV/HV states and update the reference densities.
  2. Update the Feedback Linearization terms \(F_c\) and \(G_c\).
  3. Compute the null space of \(G_c\) and construct candidate right inverses \(H_c\).
  4. Map the physical control bounds into virtual-input constraints.
  5. Solve MPC for the candidate mappings and select the minimum-cost solution.
  6. Convert \(\nu_c^{*}\) into \(u_c^{*}\) and apply the corresponding suggested velocities.

Simulation Study

The controller was evaluated on a three-lane highway divided into eight 2-km cells. Cells \(C_4\), \(C_5\), and \(C_6\) were initially congested, with \(C_4\) and \(C_6\) close to jam conditions. Suggested velocities were applied to cells \(C_3\) through \(C_6\).

The traffic model used a 5-second simulation time step and a 1-minute MPC control period, with prediction and control horizons \(N_p=20\) and \(N_u=10\). Three cases were compared: no control, control of both AVs and HVs, and control of AVs only.

68 min No Control
62 min AV-Only Control · 9% Faster
60 min AV + HV Control · 11% Faster

Without control, congestion cleared after approximately 68 minutes. Controlling both classes reduced this to approximately 60 minutes. Importantly, applying commands only to AVs cleared congestion in approximately 62 minutes—nearly the improvement obtained by controlling both classes, but with fewer interventions.

How Does the Controller Reduce Congestion?

The controller redistributes traffic in space rather than simply maximizing instantaneous flow. In the simulations, vehicles are temporarily concentrated upstream so that the downstream congested region can recover more quickly.

In the AV-only case, the controller frequently recommends a lower velocity in cell \(C_3\), reducing inflow into congested cell \(C_4\). Cell \(C_6\), in contrast, often receives no restrictive command, allowing vehicles to leave the congested region as quickly as the traffic state permits. After congestion is relieved, the controlled highway exhibits smoother and higher traffic flow.

Key Contributions & Takeaways

  • A hybrid FL–MPC framework for nonlinear heterogeneous highway traffic with bounded speed commands.
  • A null-space-based constraint-mapping method linking physical input limits to FL virtual commands in an over-actuated system.
  • A real-time AV/HV reference-density generation method adapting to congestion and traffic composition.
  • Simulations show that controlling only AVs can still substantially reduce congestion, with clearance time close to controlling both classes.
